# Style

Durable code and documentation style conventions for this repo.
Anchored on [`AGENTS.md`](../AGENTS.md) Code Style section, expanded with plans/*.md conventions.

## Python Code

- **Explicit and readable over clever.** Type hints on all public functions; prefer descriptive names over compact expressions.
- **No lambdas or nested functions in schema variable sources.** They must remain picklable for process workers (`_variable.py`, `schema.py`).
- **Pure source functions in schema.** Variable-projection functions must be pure — they project from `VariableContext`. I/O belongs in `_streaming.py` and `ingestor.py`.
- **Fail fast in config.** Validate `MtgFciL1cConfig` fields in `__post_init__`. Reject invalid values at config construction time, not deep in the pipeline.
- **Type-check clean.** `uv run --frozen mypy src/` must pass with zero errors. Use `# type: ignore[<code>]` sparingly and only with a specific error code.
- **Lint clean.** `uv run --frozen ruff check src/ tests/` must pass. Do not add new `# noqa` markers without a comment justifying them.
- **Test alongside behavior changes.** New behavior gets a test in the same PR. Refactors that don't change behavior may omit test additions but must not remove existing coverage.

## Docs

- **Public docs are user-focused.** Reader tasks, commands, expected output, verification, troubleshooting. See `.prompts/docs-policy.md`.
- **No implementation history, audit notes, or private module paths** in public docs.
- **Link, don't duplicate.** For core mechanics (direct-region Zarr, parallel writes), link to Firecube public docs.
- **Contributor material lives in `docs/contributing/`.** Root README is user/operator focused.
- **Notebooks under `docs/examples/`.** Use `.prompts/write-example-notebook.md`.


## Plans/*.md

- **DESIGN.md** — locked architectural invariants. Change requires a DONE.md entry documenting the exception.
- **TODO.md** — accepted work only, `§N` numbered. Include: Goal, Trigger (if event-driven), Decision (with date), Design constraints (numbered), Acceptance criteria, References.
- **DONE.md** — dated log (`## YYYY-MM-DD — title`), newest at top. Records decisions AND release completion notes.
- **IDEAS.md** — speculative, "## Idea N" numbered. Each idea has: What, Why we might want it, Why not yet, Open questions.
- **STYLE.md** — this file. Durable style rules that transcend a single release.
- **TESTING_STANDARDS.md** — test-quality rules adopted from firecube-core. Behavior-first, forbidden patterns, review checklist.

## File Layout

- `src/firecube_mtg_fci_l1c/` — production code
- `tests/` — pytest test files, mirror source structure
- `docs/` — public user/operator docs
- `docs/contributing/` — contributor-only docs
- `docs/assets/` — binary assets; each needs a sibling `.ABOUT` file per QA rules
- `plans/` — internal design docs (DESIGN, TODO, DONE, IDEAS, STYLE)
- `.reports/` — generated SBOM and license reports; git-ignored, regenerated locally
- `scripts/` — helper scripts for common operator workflows

## Testing

- **Standard**: see [TESTING_STANDARDS.md](TESTING_STANDARDS.md) for test-quality rules (behavior-first, forbidden patterns, review checklist). Adopted from firecube-core's testing standard.
- **Framework**: pytest, run via `uv run --frozen pytest tests/ -q`.
- **Fixtures**: `tests/conftest.py` for shared setup.
- **Golden snapshots**: `tests/golden/*.json` for schema and output invariants; regenerated by running the pinned regenerator (not by hand-editing).
- **Test naming**: `test_<subject>_<behavior>.py` at file level; `test_<what_it_verifies>` at function level.

## Dependencies

- **Runtime**: kept minimal (firecube, xarray, numpy, h5netcdf).
- **Dev**: pytest, ruff, mypy, matplotlib (notebooks), pyproj (projection CRS oracle tests).
- **Never pin unreleased core versions.** `firecube>=X.Y.Z` may only reference a tagged PyPI release.
- **`uv.lock` is regenerated automatically** by `uv sync`; do not hand-edit.
